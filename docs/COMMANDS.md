# חבילת פקודות: מה לכתוב ל-Claude Code

משפטים מוכנים להדבקה. מחליפים את מה שבסוגריים המשולשים. Claude Code יבחר בכלים המתאימים, ויעצור לאישור איפה שההוראות אומרות.

הכלי מודד ולא שומע. כל פקודה כאן מסתיימת במדידה או בדוח, וההחלטה אם זה נשמע טוב נשארת אצלך.

## לפני הכול

| מה רוצים | מה כותבים |
|---|---|
| לבדוק שההתקנה תקינה | `תריץ py -m track2ableton.doctor ותגיד לי מה חסר ומה הפקודה שמתקנת כל דבר` |
| להתקין או לעדכן את הגשר ל-Ableton | `תריץ py -m track2ableton.doctor --install-bridge ותגיד לי מתי להפעיל מחדש את Live` |
| לראות מה יש בפרויקט | `תראה לי את הערוצים, הדיווייסים והטמפו של הפרויקט הפתוח` |
| לדעת מה שונה | `תראה לי את היומן: מה שינית בפרויקט בסשן הזה` |
| לבטל | `תבטל את השינוי האחרון` |

**מצב קריאה בלבד:**

```bash
py -m track2ableton.doctor --read-only on
```

מאותו רגע אפשר להסתכל, למדוד ולנתח, וכל פקודה שמשנה את הפרויקט או מפעילה ניגון נדחית. ההגנה נאכפת בתוך הגשר שרץ ב-Ableton, ולכן היא חלה על כל תוכנה שמדברת איתו, ולא רק על Claude Code. היא נכנסת לתוקף מיד, בלי להפעיל שום דבר מחדש. לכיבוי: אותה פקודה עם `off`. הגשר הישן לא מכיר את המצב הזה, אז אחרי עדכון צריך להתקין אותו מחדש (`--install-bridge`) ולהפעיל מחדש את Live.

**היומן:** כל שינוי שנשלח ל-Live נרשם בתיקייה `.track2ableton/journal` שבתיקיית הבית שלך: שעה, פקודה, פרמטרים ותוצאה. שמות ערוצים ונתיבי קבצים נשמרים שם כמו שנשלחו. קבצים בני יותר מ-60 יום נמחקים. לכיבוי: משתנה הסביבה `T2A_JOURNAL=0`.

## שכבות ומיקס

| מה רוצים | מה כותבים |
|---|---|
| לדעת מי מתנגש במי | `ייצאתי את הסטמים ל-<תיקייה>, כולם מתיבה 1. תריץ clash_report עם הטמפו של הפרויקט ותגיד לי אילו זוגות מתנגשים, באיזה תחום ובאילו תיבות` |
| לבחור לופ שמתאים | `יש לי את הלופים האלה: <קבצים>. תריץ fit_layers מול הסטמים שכבר יש, ותדרג אותם לפי כמה מקום פנוי כל אחד מוצא` |
| דוח מיקס | `תריץ mix_report על הסטמים ותגיד לי סדר עוצמות, בעיות ו-headroom` |
| לראות סאונד | `תראה לי waveform וספקטרוגרמה של <קובץ>` |

שני הכלים הראשונים צריכים קבצים שמתחילים באותו רגע ובאותו טמפו.

## מאסטרינג מול רפרנס

1. `ייצאתי את המיקס ל-<mix.wav>. הרפרנס הוא <ref.wav>. תריץ match_reference ותראה לי את השרשרת המוצעת לפני שאתה נוגע במשהו`
2. `תחיל את השרשרת על המאסטר. לפני כל דיווייס תקרא את הפרמטרים שלו עם get_device, ותקבע לפי ערכי תצוגה`
3. מייצאים את המאסטר.
4. `ייצאתי ל-<master.wav>. תריץ verify_reference מול אותו רפרנס ותגיד לי מה עבר ומה עדיין רחוק`

חוזרים על 2 עד 4 עד שהבדיקה עוברת, או עד שהאוזן אומרת שמספיק.
